# Go stdlib oracles

Ground truth for guff's ports of Go standard-library parsers, generated by
running the **real standard library** over a deterministic corpus.

```bash
./compat/oracles/regen.sh              # all
./compat/oracles/regen.sh gotime       # one
```

## Why these exist

Five staticcheck checks are not really checks at all — they hand a constant to
the standard library and print `err.Error()` verbatim:

| Check | Upstream body |
|-------|---------------|
| SA1000 | `regexp.Compile(s)` |
| SA1001 | `template.New("").Parse(s)` |
| SA1002 | `time.Parse(s, s)` after `_`→` `, `Z`→`-` |
| SA1007 | `url.Parse(s)` |
| SA5009 | Go's `printf` grammar |

For these, "port the check" means "port the parser". Anything else diverges
twice over: a Rust crate accepts a *different set of inputs* — so guff reports
findings upstream does not, and misses ones it does — and words its errors
differently, so even an agreeing verdict fails the golden gate. The SA1002
heuristic reported `time.Parse("not-a-layout", …)`, which Go parses fine, for as
long as it existed; `url::Url` rejects `foobar` and `mailto:a@b.c`, which Go
accepts, so SA1007 carried hand-written exceptions for shapes nobody had
enumerated.

A port is only worth more than the approximation if it is *verified* to be one.
That is what these oracles are for: the Rust side replays the same corpus and
must agree on every row, so an expected value is never written by hand — the
same rule [`../golden`](../golden/README.md) follows.

## Layout

| Oracle | Output | Port it gates |
|--------|--------|---------------|
| `gotime` | `crates/guff-staticcheck/tests/testdata/gostd/time_parse.tsv` | `gostd::time` (SA1002) |
| `gourl` | `crates/guff-staticcheck/tests/testdata/gostd/url_parse.tsv` | `gostd::url`, `gostd::netip` (SA1007) |
| `goquote` | `crates/guff-staticcheck/tests/testdata/gostd/quote.tsv` | `gostd::strconv` |
| `goquote-table` | `crates/guff-staticcheck/src/gostd/isprint_table.rs` | `gostd::strconv::is_print` |

The Rust side is `crates/guff-staticcheck/tests/gostd_*.rs`.

`goquote-table` is the one output that is source rather than testdata.
`strconv.IsPrint` is pinned to the Unicode version Go's own tables carry, and a
Rust category crate on any other version disagrees on every code point assigned
in between — 5812 of them between Go 1.26 and `unicode-general-category` 1.x.
Go's `strconv` ships a generated table for the same reason, so guff keeps a copy
of Go's rather than deriving one. `quote.tsv` is what gates it: the test checks
`is_print` for **every** rune against Go's answer.

## Format

Two or three tab-separated columns, one row per corpus entry:

```
<Go-quoted input>	<hex of input bytes>	<result, verbatim>
```

The first column is for humans reading a diff. The second is what the test
replays, because an input may hold bytes that are not valid UTF-8. The third
needs no encoding: every message goes through `strconv.Quote` or `time.quote`,
so it can never contain a tab or a newline — and `gourl` fails loudly if one
ever does.

## Go version, and what pins it

Regenerate under a different Go toolchain and rows will move. That is the point:
each move is a behaviour change users would see, so read the diff.

Every oracle's `go.mod` pins `go 1.25.0`, which is **golangci-lint v2.12.2's own
go directive** — not a guess about what is new enough to compile. GODEBUG
defaults are derived from the main module's directive, so that line is what
decides which behaviour the standard library gives golangci-lint, and therefore
which behaviour guff has to reproduce.

Two couplings are worth knowing before you regenerate:

- **`urlstrictcolons`** (pinned by the directive above). Go 1.26 made
  `http`/`https` hosts take the *first* colon as the port separator rather than
  the last, behind a godebug whose default comes from the main module's go
  directive (go.dev/issue/75223). guff has to match **golangci-lint's** build,
  and v2.12.2 declares `go 1.25.0`. Bump this when golangci-lint bumps its own.
- **Unicode version** (`goquote-table`), as above.

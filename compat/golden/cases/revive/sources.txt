# Source files materialized into the case work dir before each run.
# Format: <dest-name>  <repo-relative-source-path>   (two or more spaces between)
#
# The golden tier keeps no copy of these files: it points at the fixtures the
# Rust unit tests already use, so the two can never drift.
#
# The Rust tests type-check each fixture file as a package of its own, so every
# file gets its own directory here. Where several fixtures share a package
# name, the directory is nested (<slot>/<package>/) so that the directory's
# base name still equals the package name — otherwise package-directory-mismatch
# would fire on nearly every file and drown the rest of the case.
#
# badfile/ is the deliberate exception: `bad file.go` declares `package util`
# in a directory named badfile, which is what makes it a package-directory-
# mismatch fixture as well as the filename-format one.
#
# dot/ and badalias/ are the two stub packages the fixtures import. The other
# stubs under tests/testdata/revive/stub/ shadow the standard library for the
# Rust type-checker; here the real standard library is on hand, so they are not
# carried over.

# extended_bad_test.go is an external test package (`util_test`), and it gets a
# directory of its own rather than sitting next to extended_bad.go. Upstream's
# package-naming rule memoizes per directory (`alreadyCheckedNames.AddIfAbsent`)
# and revive lints a package's files concurrently, so in a multi-file directory
# *which* file wins the memo — and therefore whether the package name checked is
# "util" or "util_test" — is a race. Measured on revive v1.15.0: a three-file
# package reported at a different file on three consecutive runs. One file per
# directory is what makes this case's positions reproducible.
